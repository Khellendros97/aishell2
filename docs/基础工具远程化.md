# 基础工具远程化（read/grep/find/ls/write/edit/delete_path 支持 serverId）

> 设计文档：基础工具远程读写、优先工具而非命令、与文件暂存自动备份的集成。
> 对应实现：`src-tauri/src/pi_ext/aishell-guard.ts`（覆盖注册/权限）、`src-tauri/src/ai_actions.rs`（remote_* 动作族）、
> `src-tauri/src/ai.rs`（动作分发/事件适配/系统提示）、`src/pages/workbench/ai.ts`（动作卡/暂存刷新）。

## 动机

- 此前 AI 操作远程文件只有两条路：`run_command`（cat/sed/echo/tee…）或 `sftp_upload/download`。
- `run_command` 写远程文件虽经 `analyze_remote_command` 影响分析 + 快照，但分析是静态规则、易漏（变量/循环/外部脚本一律 unbounded，
  且模型可能用 `sed -i` 之类绕过语义识别），且「命令操作文件」对模型而言是低约束路径——**改动没有可靠落到会话暂存自动备份**。
- 目标：基础文件工具（模型最常用）直接支持远程读写；远程写/改/删一律走受管 SFTP + `ensure_snapshot`，暂存系统成为唯一备份事实源；
  系统提示词引导模型**优先工具、不用命令碰远程文件内容**。

## 权限矩阵

| 模式 | 本地基础工具 | 远程基础工具（serverId） | run_command |
|---|---|---|---|
| suggest | ✅（原行为） | ❌ validate 阻止（提示申请工作模式） | ❌ |
| agent | ✅ | ✅ 受控工具逐调用审批（write/edit/delete_path 本就受控） | ✅ 逐调用审批 |
| yolo | ✅ | ✅ 直接执行 | ✅ 直接执行 |

远程能力仅 agent/yolo：`validate()` 对带 `serverId` 的七工具调用先查模式，suggest 直接 block。
服务器 AI 操作锁在 Rust `ensure_ai_allowed` 入口统一拦截（与 run_command/sftp_* 一致）。

## 工具寻址协议

- 六个基础工具 + `delete_path` 的 schema 追加**可选 `serverId`**（`SERVER_ID_PARAM`）：不传 = 本地项目目录（行为与内置完全一致）；
  传入 = 操作该服务器。
- 远程 `path`：POSIX 绝对路径（`/` 开头）或相对服务器登录目录（remote_home）的相对路径；盘符形态（`C:`）与 UNC 被拒绝。
- `serverId` 用 `list_servers` 获取，禁止编造（系统提示已有）。

## 实现机制

### 1. 同名覆盖（aishell-guard.ts）

pi 支持扩展以同名注册覆盖内置工具（`read/bash/edit/write/grep/find/ls`）。guard 用
`createXxxTool(cwd, { operations })` 工厂构造覆盖版：

- **无 serverId** → 委托 `localXxx.execute(...)`（本地实例 = `createXxxTool(cwd)` 无 operations，行为与内置一致；
  本地 find/grep 仍走 fd/rg 二进制路径）。
- **有 serverId** → 构造远程 operations，全部经 `AISHELL_ACTION:` 桥（`rustActionEx`）调 Rust `remote_*` 动作。
- **假路径映射**：工具 core 内部用 `path.resolve(cwd, p)` 解析路径后传给 operations。远程调用时 wrapper 预计算同一结果
  （`makePathMap`），建 `假路径(小写) → 原始远程路径` 反查表（含父目录，供 write 的 mkdir）；operations 收到假路径即还原。
  单次调用内确定性、无碰撞（edit 只操作单文件）。
- **远程 grep 例外**：内置 grep core 强制 spawn 本地 rg，无法远程复用 → 自定义 execute，走 `remote_grep` 受管模板命令
  （`grep -rn --color=never [-i] [-F] [-C n] [--include=glob] -e <pattern> -- <path>`，全参数 shell_quote，
  只读、30s 超时、退出码 1=无匹配、127=服务器未装 grep 降级报错）。
- **ls 优化**：`remote_listdir` 一次返回带 isDir 的条目，ops.stat 用 readdir 缓存，每次 ls 仅 2 次往返（exists/stat + readdir）。

### 2. Rust remote_* 动作族（ai_actions.rs）

全部入口先 `ensure_ai_allowed(server_id)`；相对路径经 `remote_home` 拼接后走 `canonical_remote_path` 词法折叠
（与暂存键同源归一）：

| 动作 | 实现要点 |
|---|---|
| `remote_stat` | sftp.metadata → `{exists,isDir,size,mtime}`；不存在 → exists:false |
| `remote_read` | 字节读取；>5MB / 前 8KB 含 NUL / 非 UTF-8 → 中文拒绝（远程暂不支持二进制/图片）；**不脱敏**（见下） |
| `remote_mkdir` | 逐级 sftp.mkdir（已存在跳过、非目录报错），纯 SFTP 不依赖 shell |
| `remote_write` | 目录目标拒绝 → 自动备份开启时 `ensure_snapshot`（失败阻止写入）→ 父目录自动创建 → sftp.create+write → `refresh_current` |
| `remote_listdir` | read_dir → `[{name,isDir,size,mtime}]`（ls 缓存源） |
| `remote_glob` | SFTP 递归 walk（深度 ≤12、目录 ≤2000），glob→regex（`*`=`[^/]*`、`**`=`.*`、`?`=`[^/]`、字符类透传），
  含 `/` 匹配完整相对路径、不含 `/` 只匹配 basename（对齐 rg 惯例）；跳过 node_modules/.git；返回相对路径 |
| `remote_grep` | 受管模板命令（见上），输出脱敏 + 截断（同 run_command 标准） |
| `remote_delete` | 仅文件（目录删除引导 run_command，其影响分析会枚举目录文件逐一快照）；删除前 `ensure_snapshot`（可还原）→ sftp.remove → `refresh_current` |

### 3. 暂存集成（核心目标）

自动备份开启时（`auto_backup_remote_files`）：
- `remote_write` / `remote_delete` 在执行前对**最终目标绝对路径** `ensure_snapshot`——同一会话首次修改记录原始字节
  （新建文件记 Absent），快照失败即阻止操作；执行后 `refresh_current`。
- 与 run_command/sftp_upload 共用一个 `RemoteStaging`（同 manifest、同会话），暂存面板/`staging_list`/`staging_diff`/`staging_restore` 直接可见可还原。
- 影响分析：单文件目标天然 bounded（无需 LLM/静态分析），因此远程 write/edit/delete **不登记 ImpactEntry**；
  审批卡意图文案注明「写入前自动备份原文件到会话暂存区」。

### 4. 事件与前端（ai.rs / ai.ts）

- `tool_execution_start`：远程 write/edit（args 带 serverId）**不登记 pending_paths** → 不发 `fs:changed`（远端文件无本地编辑器）。
- `actionStart` args 透传 serverId → 前端 `ActionCard.serverId`；`argsIntent` 显示「写远程文件 …（服务器 …）」。
- `actionEnd`：远程 write/edit/delete_path 额外广播 `staging-changed`（刷新暂存面板与输入区计数）；
  本地 write/edit 保持只走 fs:changed。

### 5. 系统提示（SYSTEM_PROMPT_AGENT）

新增指引：远程文件内容查看/修改**优先**基础工具 + serverId（自动备份可还原）；**禁止**用 run_command 的 cat/sed/echo/tee 等
读写远程文件内容（绕过受管备份）；run_command 定位为服务管理、进程、包管理等非文件内容操作。suggest 提示不变。

## 脱敏权衡

- `remote_read` / 编辑链路的内部读 **不脱敏**：与本地 read/write 一致；脱敏会破坏 edit 的 oldText 精确匹配（把 `***已脱敏***`
  写回文件即损坏）。凭据纪律由系统提示约束（与本地项目内文件同信任级）。
- `remote_grep` 输出 **脱敏**（`redact_secrets`）：批量内容扫描接近命令输出语义，与 run_command 输出同标准。

## 边界与失败模式

- 服务器锁定 → 全部 remote_* 拒绝（不 kill 用户连接）。
- 自动备份关闭 → 远程写照常执行，仅无快照（与 run_command 现状一致）。
- 远程大文件/二进制读 → 中文错误（引导 run_command head/tail 审批路径）。
- grep 依赖服务器装有 grep；127 退出码降级为中文错误并建议 read/find。
- abort/取消：pi abort → extension_ui_request cancelled → 桥抛「操作已被取消」（现有机制）。
- 并发：write/edit 经 core `withFileMutationQueue` + staging 每键 async 锁双保险。
